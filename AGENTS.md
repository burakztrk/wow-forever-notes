# AGENTS.md

WoW Forever Notes — static Astro 7 blog (GitHub Pages) with daily WoW Forever beta patch-note summaries in
Turkish and English, plus hover tooltips for spells, talents and racials.

## Commands

```bash
npm ci
npm run dev            # http://localhost:4321/ (drafts visible)
npm run build          # production build (drafts skipped); fails on bad glossary references or missing translations
npm test               # vitest: parsers, update detection, glossary/remark plugin, TR/EN pairing
npm run sync           # refresh src/data/*.json + public/icons/ from wclbox (~10 min first run, cached in .cache/http)
npm run sync:professions   # only professions.json + legacy.json (+ icons); prints GUIDE_OUTDATED / TRANSLATE_PENDING
npm run check-updates  # NO_UPDATES | UPDATES_FOUND (details in .cache/updates.json) | ERROR
npm run check-updates -- --mark-seen   # advance src/data/state.json after publishing
npm run check-updates -- --from 2026-10-01   # backfill: one group per build since that date; skips builds that already have a post
npm run check-updates -- --since 1.60.1.70374   # test mode: treat that build as last published; state.json untouched
npm run translate      # apply src/data/i18n/tr.json to the glossary; lists missing Turkish texts
npm run translate -- --apply <file.json>   # merge new translations (validated: numbers must survive)
```

Node 22.12+.

## Layout

- `src/config.ts` — `DEFAULT_LANG` (root redirect target) and `LANGS`.
- `src/content/blog/{tr,en}/<slug>.md` — one file per language, same slug. Schema: `src/content.config.ts`.
- `src/data/glossary.json` — spells, talents, racials (generated; do not hand-edit except `descTr`).
  `races.json`, `classes.json` — race→class matrix, talent trees (for the future class/race pages).
  `state.json` — what check-updates has already seen.
- `src/lib/remark-sections.ts` + `src/lib/post-sections.ts` — `::class[…]`, `::race[…]`, `::profession[…]` leaf directives
  split a post into collapsible `<details class="note-section">` blocks (unknown names fail the build; TR and EN must
  have the same sections). `components/PatchNotes.astro` lists them near the top of the class and race pages and in
  a closed section of the professions page (collapsed, newest first). `/data/v1/posts.json` sends them as `<section>` in `html` plus a `sections` array.
- `src/lib/remark-glossary.ts` — `:spell[…]`, `:talent[…]`, `:racial[…]`, `:tip[…]` directives → tooltip spans;
  auto-links unambiguous multi-word names; unknown names fail the build.
- `src/scripts/tooltip.ts` + `src/lib/tooltip-render.ts` — client tooltip (event delegation, floating-ui).
- `src/pages/[lang]/{races,classes,stats,search}/` — race, class and search pages. URLs: `/<lang>/classes/` is the classes list (nav "Class'lar"), `/<lang>/classes/<class>/` is the class's **story** (`classes/<class>.astro`), `/<lang>/stats/<class>/` its skills, patch notes and stats (`stats/[cls].astro`, the old `classes/[cls]`). Races work the same way: `/<lang>/races/` is the list, `/<lang>/races/<slug>/` (`human`, `night-elf`, `skyborne`, …) the race's **story** (`races/<slug>.astro`), `/<lang>/stats/<race id>/` (`alliance-human`, …) its racials, patch notes and classes (`stats/[race].astro`, the old `races/[race]`); `/<lang>/stories/` is only the stories index and timeline. The chip strip (`ClassChips.astro` / `RaceChips.astro`) sits centred across the hero and `HeroTransition.astro` gives the switch between two stories its view-transition animation (hero wipe, title slide); a new story page needs `<ClassChips/>` or `<RaceChips/>` as the first child of `.hero-in`. Build story links with `storyUrl()` / `statsUrl()` (`src/lib/stories/urls.ts`); the old `/<lang>/stories/<class or race>/` and `/<lang>/races/<race id>/` URLs redirect (astro.config). The races list cards open the race's story; the planner pages stay at `/<lang>/talents/<class>/`, reached from the class page's talent banner, and `/<lang>/talents/` redirects to the list), same rules as the mobile app (`src/lib/codex.ts`,
  `src/lib/search.ts`; vectors in `tests/codex.test.ts`, `tests/search.test.ts`). Saved talent builds live in localStorage
  (`src/lib/saved-builds.ts`, same shape as the app's `BuildStore`); characters saved from the creator too
  (`src/lib/saved-characters.ts`, the app's `CharacterStore`; `?character=<id>` makes the planner's Save write into
  the character). Change both sides together.
- `src/pages/[lang]/index.astro` + `src/styles/dashboard.css` — home page: a dashboard like the app's Home (search, latest
  patch note, "Create a character" tile, one tile per feature with a live count; saved-build count from localStorage).
  Its icons are the app's navigation icons: `src/lib/codex-icons.ts` is generated by the mobile repo's
  `docs/icon-concepts/nav/nav_icons.py --web <path>` (don't hand-edit), `components/CodexIcon.astro` draws one in currentColor.
  Old `/<lang>/#race=…&class=…` links are forwarded to the creator page.
- `src/pages/[lang]/creator/index.astro` + `src/scripts/combo.ts` + `src/styles/combo.css` — in-game style race/class screen
  (races left, classes bottom, racial/class panels right; state in `#race=…&class=…`), the app's CreatorScreen.
- `src/pages/[lang]/professions/` + `src/pages/[lang]/legacy/` — professions: seven `<details class="fold">` sections in
  this order, primary and secondary profession cards open, then camping, camp buffs, best pair per class, patch notes and
  sources closed (a jump link or `#id` URL opens its section; same order and defaults as the app's ProfessionsScreen),
  one page per profession (tools, camp objects, materials, 1–300 route, gathering zones) and the
  Legacy page with a 3-tree calculator. Data: `src/data/professions.json` and `legacy.json` (generated by
  `scripts/sync/professions*.ts` from wclbox and the wowforevertools Legacy chunk) joined with the hand-edited
  `src/data/professions-guide.json` (camping text, buff table, class picks and reasons, tools, blueprint drops; TR + EN)
  in `src/lib/professions.ts`. The Legacy calculator reuses `talent-rules.ts` with its 16-point cap and
  `scripts/talents.ts`; the share code works like the class trees (`#b=…`). Items, camp objects and Legacy perks get
  card tooltips (`CardTip` in `tooltip-render.ts`, `ItemTip.astro`); spell names in the guide's prose become glossary
  tooltips (`RichText.astro`). The app reads the same data from `/data/v1/professions.json` (with the guide) and
  `/data/v1/legacy.json`.
- `src/pages/[lang]/stories/` — race and class stories ("Hikayeler"/"Stories" in the nav, before the search icon): the index shows the
  Alliance and Horde races as two scroll-snap carousels, one below the other (`components/stories/StoryCarousel.astro`, slides and order in `src/lib/stories/slides.ts`, behaviour in `src/scripts/story-carousel.ts`; the home page opens with `components/stories/StoryMarquee.astro` (CSS only; each icon links to its race or class page, no search bar on the home page any more) and shows the same carousel below it: timeline first, then every race once; three rows of squircle race/class icons gliding in alternating directions, every second row shifted half an icon;
  the Skyborne come last in both), then the classes; each written race is one scroll-told page (`gnome.astro`,
  `dwarf.astro`, `human.astro`, `night-elf.astro`, `orc.astro`, `troll.astro`, `tauren.astro`, `undead.astro`, `skyborne.astro`). `curse-of-flesh.astro` is a shorter lore page that is listed nowhere (index, race strip,
  nav, search): only the origin chapters that mention the curse link to it (`CurseLink.astro`, `curseUrl()`).
  The race strip, written-story slugs and next-story links come from `src/lib/stories/races.ts` (a people on both sides is one entry: the Skyborne have `faction: 'ah'`, a half blue, half red chip dot, and `ids` for both race ids, so `storySlug()` answers `skyborne` for either);
  header, race strip and closing/notes are `src/components/stories/*.astro`. Copy, TR + EN, in `src/i18n/stories.ts`
  (`STORY_UI` holds the strings every page shares). Maps and drawings in `src/lib/stories/<race>-art.ts`, generated by
  `python3 scripts/stories/<race>_art.py` (stdlib only, seeded; shared helpers in `art_lib.py`; `%%key%%` labels are
  filled per language by `src/lib/stories/art.ts`). Scroll effects in `src/scripts/story.ts`, driven by markup:
  `data-p="start,end"` sets `--p`; `data-routes` draws route masks (`data-r`, `data-show`); `data-moves` drifts parts
  with `data-move="dx,dy,deg"`; the `#ek` map's `data-cams` holds one camera per step; `canvas#snow[data-fx]` is
  `snow` (blizzard), `cinders` (small red flames that fall and cool to grey ash), `embers` (forge sparks), `void` (violet motes), `wisps` (moonlit wisps), `voodoo` (jungle-green motes), `plague` (blight-green motes), `sun` (prairie-gold motes) or `gale` (pale blue wind lines). Styles in `src/styles/stories.css`, all scoped under `.lore`; images
  in `public/stories/<race>/`; cover art (hero background, index card) comes from the site owner, so a new story gets no drawn
  cover: leave it plain until the image arrives (the Skyborne hero is a plain sky gradient with the `gale` effect; its Zephras Isle, Feralas and Azeroth maps are WoW Forever maps in `public/maps/`). Where the lore sources disagree (the Skyborne's), the copy says so and the card carries a "disputed" or "single source" status. Proper names in the Gnome, Dwarf, Human, Night Elf, Orc, Troll, Tauren, Undead and Skyborne stories get lore cards: `src/i18n/lore.ts` (TR + EN, `aliases` are
  the exact spellings in the copy, `icon` from `public/icons`) and `src/lib/stories/lore.ts` (`loreHtml()` wraps the first
  mention of each name per text block, `loreTips(lang, loreIds, glossaryIds)` builds the `#wf-glossary` island, and the Skyborne page passes the racial ids it lists as `GlossaryRow`s; `CardTip` kind `lore`). Lore cards
  are searchable too: `loreSearch()` adds them, with their aliases and story links, to `/<lang>/search.json`;
  a new written story goes into `LORE_STORIES` (the lore test checks it against `STORY_RACES`).
- Talent planner banner on each class page (`components/stories/TalentBanner.astro`, replaces the plain link): one cover for every class, `public/stories/talent-tree.webp` (optional; without the file it shows a gradient in the class colour; the file is picked up automatically).
- Story heroes end with two link cards (`components/stories/StoryLinks.astro`, `.hero-links`): class story → `/classes/<class>/` ("Skills, Class Notes & Stats") and the talent planner; race story → `/races/<race>/` ("Racials, Race Notes & Stats") and `/creator/#race=<race id>` (the creator with that race selected). A new written story needs `<StoryLinks … />` before its hero's closing `</section>`.
- Class story covers: `public/stories/class/<class>.webp` (letterbox bars cropped off), registered in `src/lib/stories/classes.ts` (`cover`); each class story's hero background and the banner on its class page (and `story.cover` in `/data/v1/classes.json`) use it.
- `src/pages/[lang]/stories/timeline.astro` — story timeline: the major events of the race and class stories as a
  poster-style timeline (a red line with era markers, event cards alternating above and below it, each with its topic
  icons; the key of topics above it), scrolled sideways (buttons, mouse drag). The selected event is shown on the Azeroth
  map below (same coordinates as the story drawings; places off that map, like Northrend, Draenor and Skywall, are dashed
  symbolic pins) with its full text and chapter links. One filter at a time, a story or a topic (`#e=<event>&s=<slug>` / `&c=<topic>`).
  Events, places and story-chapter links in `src/lib/stories/timeline.ts`, copy (TR + EN) in `src/i18n/timeline.ts`,
  behaviour in `src/scripts/timeline.ts`, styles in `src/styles/timeline.css`. Story pages link to their filtered view
  (header + closing section). A new written story needs at least one event (`tests/timeline.test.ts` checks it).
- SEO + analytics: `src/layouts/BaseLayout.astro` writes canonical, hreflang (+ x-default), Open Graph/Twitter
  (`public/og/<lang>.png`) and an optional JSON-LD block (`src/lib/seo.ts`: `WebSite` + SearchAction on the home pages,
  `BlogPosting` on posts). `@astrojs/sitemap` (astro.config, tr/en alternates; root redirect and 404 left out) and
  `src/pages/robots.txt.ts`. Cloudflare Web Analytics (cookie-free) is added only in production builds when
  `PUBLIC_CF_WEB_ANALYTICS_TOKEN` is set — the deploy workflow fills it from the `CF_WEB_ANALYTICS_TOKEN` repository
  variable. Keep the privacy page (`src/i18n/privacy.ts`) in line with it.
- App mode: the mobile app shows the stories in a web view whose User-Agent ends in `ForeverCampfire/<version>`.
  An inline script in `BaseLayout.astro` then adds `html.in-app` (global.css hides the site header and footer and
  turns off tap highlight, text selection and the long-press menu), turns off pinch zoom and skips the Cloudflare
  beacon (the app's own statistics, with their off switch, cover those screens). Links inside a page are routed by
  the app (another story = a new app screen, race/class/talent links = its native screens). Any page works in app
  mode, so keep `.site-header` / `.site-footer` as the only chrome. `/data/v1/races.json` and `classes.json` carry
  `story` (slug, site-relative cover, lead in TR + EN, or null; `src/lib/stories/refs.ts`) for the app's story banners.
- `scripts/sync/` — wclbox parsers (`parse.ts`), wowforevertools chunk reader (`wowforevertools.ts`, acorn, literals only — never eval) and the sync entry point. `scripts/check-updates.ts`.
- `docs/scheduled-job.md` — instructions for the daily scheduled writer job.

## Rules

- Every hardcoded root-relative URL goes through `withBase()` (`src/utils/url.ts`); the site is served from the root of foreverwow.app (base `/`).
- Posts: TR and EN together, game names stay English in both, no copied source text, nothing that is not in the sources.
- Credit wclbox (named "wclbox" in the footer, with a link; every tooltip links the source page) — already in place. wowforevertools (description text) is credited in the footer and README.
- Sync etiquette: ≤2 requests/second, identifying User-Agent, cache on disk. bluetracker.gg and mobalytics.gg block bots.
- Professions guide: anything it names (profession slugs, camp object names) must exist in the synced data —
  `npm run sync:professions` prints GUIDE_OUTDATED and `tests/professions.test.ts` fails otherwise. When a new build
  changes buff values, class picks or blueprint drops, edit the guide by hand (both languages) and bump `updated`.
  Classic WoW Forever's content is CC BY 4.0: credit it with a link (page sources + footer). Legacy perk text is
  translated through the shared `src/data/i18n/tr.json` cache (`npm run translate`).
- Public repo: no secrets, `.env*` is gitignored; scan before pushing.
- Code comments and UI strings in English; Turkish lives in `src/i18n` and `src/content/blog/tr`.
